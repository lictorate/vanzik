# Vanzik 2.1.0 — Release Notes

**Released:** not yet (unreleased)
**Headline:** A security release. The firewall now reads a model's response the way the client SDKs do, or refuses it.

> **Check these before you upgrade.**
> - Some responses that used to pass are now refused: tool calls the firewall and the client SDKs would read differently, and responses it can't decode that carry a tool call. Each refusal names its rule and writes an audit entry.
> - Approvals are bound to the exact arguments. Upgrade the central server **first**: a server older than 2.1.0 ignores the binding.
> - Keyless mode accepts only a loopback `Host` from the same origin. A tunnel, a reverse proxy, `host.docker.internal` or another localhost origin now needs `--api-key`.
> - The bundled policies deny more, but an existing policy is not rewritten: copy the blocks from `configs/` to get the new rules.
>
> The full list is in [`COMPATIBILITY.md` § Security fixes in 2.1.0](https://github.com/lictorate/vanzik/blob/v2.1.0/docs/COMPATIBILITY.md#security-fixes-in-210).

---

## Why this release exists

Vanzik sits between an agent and its tools, and between an agent and its model. The LLM API Proxy reads each response from OpenAI or Anthropic, finds the tool calls in it and checks them against your policy before the agent's SDK sees them. That only works if the firewall reads the response the same way the SDK does.

A review of 2.0 found several places where it didn't. A compressed response, a legacy `function_call`, a line ending in a bare CR, a key spelled `Tool_Calls`, an Anthropic event named `ping`, a `NaN` in an unrelated field: in each case the SDK, or its tool runner, ended up with a tool call the gate never checked. The same review found that the keyless control plane could be driven by a web page, that an approval could be replayed with different arguments, and that the bundled agent policies let an agent help itself.

2.1.0 closes these. Where the firewall can read a response the way the SDKs do, it now does; where the SDKs themselves disagree, it refuses the response.

## Security fixes

### LLM API Proxy

- **Compressed responses skipped the gate (High).** The proxy forwarded the client's `Accept-Encoding`, and every stock SDK asks for compression. An encoded 2xx response failed to parse and its tool calls passed through unchecked and unaudited. Whether first-party OpenAI or Anthropic responses are ever encoded this way has not been verified; if they are, this would be Critical. The proxy now asks the upstream for gzip only and decodes it itself; anything still encoded is refused.
- **Legacy `function_call` replies were never read (High).** They are now gated like `tool_calls`.
- **OpenAI responses the SDKs read differently are refused (High):** tool names sent in fragments or mixed with `function_call`; BOM-prefixed lines and UTF-16 or UTF-32 bodies that carry a call; case-variant keys such as `Tool_Calls`; and bodies or events the firewall can't decode, such as a wrong-typed `choices` element or a `NaN` literal, that carry a tool-call key.
- **Anthropic responses the SDKs read differently are refused (High):** a `tool_use` out of its content position; input for another block during a tool cycle; case-variant, `null` or duplicate keys; a missing or `null` `partial_json`; content in `message_start`; an event whose SSE name isn't its JSON type (new rule `event_type_mismatch`); BOM-prefixed lines in a stream with a `tool_use`; and non-streaming bodies the firewall can't decode, or that carry case-variant keys.
- **SSE lines ending in a bare CR hid tool calls (High).** Lines now end at CRLF, CR or LF, as in every client SDK.
- **No upstream timeout (Low).** New flag `--upstream-header-timeout`, default `10m`.

### Server and approvals

- **The keyless control plane could be driven by a web page (High).** Pages on another localhost port and DNS-rebound pages could read pending actions and approve them, and could write a forged entry to the audit log. Keyless mode now accepts only a loopback `Host` from the same origin, and `POST /v1/audit` requires `Content-Type: application/json`.
- **Approvals were not bound to the call's arguments (High).** An approved `send_email` could be replayed to another recipient. The gates now send a keyed digest of the tool name and arguments, and the server honours an approval only for the same digest. The dashboard's pending card shows the (redacted) arguments.

### Policies, gates, setup and audit

- **The bundled policies let an agent help itself (High).** They now deny `copy_file`, `append_file`, self-approval, reading or writing Vanzik's config folder, stopping the server and editing hook settings. These are glob rules: they stop the plain forms, not a determined agent.
- **A second argument name could hide the real value (Medium).** `{"command":"ls","cmd":"rm …"}` is now denied in both gates.
- **The MCP gateway kept secret-named arguments in plain text (Medium),** and **a notification flood exhausted its memory (Medium).**
- **Coding-agent hooks let calls through while the server was down, and setup chose that (Medium).** Setup now preselects blocking.
- **Audit entries could be lost, or shutdown could hang, with a stalled audit writer (Medium).** Shutdown now waits up to 7 s and spills the rest to the overflow file.
- **CVEs in the Go standard library, zlib and OpenSSL (High).** Builds use Go 1.26.11, and the image upgrades zlib, libssl3 and libcrypto3.

## What's new

- **[Known limits](https://github.com/lictorate/vanzik/blob/v2.1.0/docs/THREAT_MODEL.md#known-limits)**, stating what 2.1.0 doesn't check: provider-executed tools, non-streaming `/v1/completions`, one argument per role, and a few others, each marked as a decision or an open gap.
- `le="0.05"` and `le="0.1"` buckets on the latency histograms, so a sub-millisecond p99 can be read.
- Counters `vanzik_llmproxy_undecodable_content_encoding_total` and `vanzik_llmproxy_event_type_mismatch_total`.

## Upgrade notes

1. **Upgrade the central server first**, then the LLM API Proxy and MCP Gateway. A pre-2.1.0 server ignores the argument binding.
2. **Give the gates `--api-key`** if the central server has one. Approvals then survive a gate restart and work across replicas, and the gates' own refusals are recorded with the verdict the client received.
3. **Copy the policy blocks** from `configs/` into your policy to get the new deny rules.
4. **Set the host's stop timeout** above the server's shutdown timeout (10 s) plus 7 s.
5. **Check anything that reaches a keyless server** through a tunnel, a reverse proxy, a container or another localhost origin: it now needs `--api-key`.

## Known limitations

See [`THREAT_MODEL.md` § Known limits](https://github.com/lictorate/vanzik/blob/v2.1.0/docs/THREAT_MODEL.md#known-limits). In short:

- Tools the model provider runs itself (Anthropic server tools, the MCP connector) are not gated or audited.
- Each call is checked on one argument per role, so a copy's source is not checked, and some alias spellings are still forwarded.
- Across PostgreSQL replicas, an approval may be honoured once per node for a few seconds after it is used, and for its whole validity when reconciliation is off. This comes from reading the code; it has not been reproduced.
- The bundled self-protection rules stop the plain forms only.
